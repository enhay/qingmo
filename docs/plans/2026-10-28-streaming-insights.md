# 轻墨流式洞察对话实施计划

## Need

用户选定速记后，可以边看模型回答边继续追问、补充和纠正理解；不必为每个问题重新生成报告。模型沿用思源设置，由 AI SDK 独立请求。原始笔记不修改。

## Context

现有 `InsightService` 使用非流式 `/api/ai/chatGPT`，前后清理共用上下文，完成后逐次创建文档。思源 3.8.8 的配置读取和 OpenAI 协议直连流已以无私人内容的请求实测通过；手机网络与真机交互尚未验证。

## Scope

- In：AI SDK 消息和流式调用、会话内追问、停止与失败处理、已核对来源、每个对话一篇原生文档、现有视角方法的对话适配；通过 REA 静态检查 flomo 客户端中可见的提示词及请求构造，按实际证据优化方法。
- Out：旧 AI 接口和历史格式兼容、自动读取范围外笔记、模型工具执行、客户端登录或私人数据调查、部署与发布。

## Binding decisions

- D1：AI SDK 是消息、流式协议和模型请求的唯一实现。`src/state/` 持有插件共享的 SDK Chat 实例；`src/core/` 负责材料、配置映射、来源校验与原生文档保存。SDK Provider 消费思源运行时配置，密钥不进入快照、共享设置、日志或文档。明确拒绝无法直连的账号登录认证，不回退旧接口。
- D2：每轮显式发送方法、固定材料快照和 SDK 消息历史。用户更换材料或视角时新建对话；保留同一插件实例中的当前对话。停止使用 SDK 的中止能力，部分文字保留为未完成，不把它自动归档为完整回答。不静默裁剪消息；超过会话材料预算则提示开启新对话。
- D3：沿用思源原生文档保存和来源定位，每次新对话创建唯一文档，完成的一轮问答追加到该文档；保存失败仅重试未保存轮次。历史读取新对话属性并在思源打开，不恢复旧结果或增加独立聊天数据库。
- D4：流式显示先作为纯文字；完整回答通过来源 ID 核对和安全 Markdown 渲染后可定位来源。未知来源不能自动归档。网络错误、停止、截断、保存错误分别显示；不自动重试付费请求。
- D5：保留六个视角与现有 Skill 作为方法唯一来源。提示词集中在回顾方法和自然交流，删减重复的非方法边界约束，来源和保存安全由代码负责。客户端逆向结果只作为参考，区分界面引导语、实际请求与未知服务端内容，不声称复原未见提示词。

## Delivery

1. 替换调用及共享状态，并交付流式对话、来源、安全和原生追加保存的完整消费路径；同步 PRD、设计和前端约定。
2. 根据 REA 静态证据更新对话方法，保留归属、反例和引用要求。
3. 用合成输入和受控 SDK 流验证追问、停止、来源拒绝和保存重试；运行现有测试、格式检查、构建和产物语法检查，再以思源配置做一次 AI SDK 真实流式验证。浏览器与真机视觉由用户验收。

## Status

本地实现完成。20 条测试、格式、构建、产物语法、受控 SDK 流、真实模型两轮对话与隔离思源保存读回通过。REA 客户端检查完成，提示词已按方法本身精简。证据见[流式洞察与 flomo 提示词核对](../design/acceptance/streaming-insights/流式洞察与flomo提示词核对.md)。浏览器视觉和手机端尚待用户验收；未推送、部署或发布。
