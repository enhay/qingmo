# 轻墨二期：已有笔记收录与本地回顾

## Need

落实 [PRD 第 6 节](../轻墨-PRD.md) 中的手动加入轻墨、标签自动收入、每日回顾和随机漫步：用户可以把散落在思源中的已有内容放进同一卡片流，保留原位置和原结构，再从回顾入口重新阅读。列表、搜索、统计和回顾使用同一批速记。交付本地实现和隔离宿主验证结果。

## Context

- 2026-10-12 的基线为 `90656c7`，仓库干净，现有 6 项 Node 测试通过；一期计划的无 Git 状态与早期桌面布局已过时。当前桌面为思源标签页两栏，移动端为全屏，侧栏使用窄屏布局。
- 当前 `src/data.js` 只查询标记超级块，编辑统一重建超级块；直接放宽查询会使已有普通块被错误改成超级块。收录查询、编辑、移出和卡片操作必须一起调整。
- 本机内核当前为 3.8.6；一期实测为 3.8.5。本轮用 `.scratch/` 内隔离工作空间和合成内容验证，不触碰个人笔记。SQL 读取继续先刷新事务。
- 块菜单接入使用官方 [petal 事件定义](https://github.com/siyuan-note/petal/blob/master/siyuan.d.ts) 的 `click-blockicon`，实际事件形状与块结构还须在本机宿主核实。
- [设计规格 2.4、2.5](../design/轻墨-design.md) 已规定视角列表与回顾卡片堆；正式回顾页是设计文档基于参考图的推断，不等于已有完整真机稿。

## Scope

- In：已有块加入与移出、固定 `#轻墨` 标签实时收录、来源定位、按块类型编辑、统一搜索统计、本地视角入口、每日固定回顾、随机漫步、相关设置与中文文案、构建和隔离宿主验证。
- Out：flomo 导入本轮暂不做，不新增原时间属性；录音转写与令牌服务仍以 V4/V5 为前置条件，本轮不实现或部署；AI 视角、付费、英文补齐和上架不在范围内。V1–V3、真机录音与跨设备同步不以本地验证代替。不改变笔记组织方式，不迁移或批量修改已有数据。

## Binding decisions

- D1：速记集合为原生标记块与标签收录块的并集，以块 ID 去重；文档不收录。新写入的轻墨速记仍为标记超级块。手动加入只设置 `custom-qingmo-memo="1"` 与 `custom-qingmo-added="1"`，不移动、不包装、不改正文。已有速记及内部子块不再提供加入入口。
- D2：标签只认原生的精确「轻墨」标签，代码、普通文字、链接、`轻墨/子标签` 不代替该开关；自动收入不写属性。标签所在段落若直接在列表项、引用或超级块内，取直接这一层容器；标题取自身。已属于收录速记的内部命中归入那一条，多个标签命中同一容器只计一次。列表、组合筛选、统计、标签树、热力图与回顾共用该集合，仍按原生 `created` 排序和计日。
- D3：原生轻墨卡片保留删除行为。外部收录卡片使用「移出轻墨」：手动加入清除两个轻墨属性，标签收入移除原生 `#轻墨` 标签；两种方式同时命中时，确认后同时清除属性与标签。移出保留块 ID、其余属性、正文结构与子块，不能整块删除，也不能顺带删除代码或链接中的同名字样。确认文案按实际是否改动原文说明。原生块菜单的「移出」也只取消收录，不删除内容。
- D4：外部卡片在非轻墨每日文档中显示「来自《文档名》」，点击定位原块。段落和超级块允许轻墨内编辑，保持原块类型、ID、收录属性及其他已有属性；其他结构交给思源编辑器。纯标签收录块编辑时不得补加速记属性；编辑会删除最后一个收录标签时先提示，成功后从卡片流退出。只有编辑已有块时不应被「先选择新建笔记本」阻挡。
- D5：视角列表只显示「每日回顾」「随机漫步」两个本地视角，不调用 AI、不显示未实现视角或 AI 范围选择。回顾从全部当前收录速记取样，不继承卡片流的临时筛选。每日回顾用本地日期作随机种子，同日保持选中 ID 与顺序；当天新增内容不重抽既有结果，移出或删除的内容不能继续展示。只存必要的本机回顾 ID，不复制正文；改变数量取同一天顺序的前 N 条，不足 N 条时展示实际数量。数量默认值与输入上限是可调整的实现参数，不成为业务契约。
- D6：随机漫步每次展示一条可用速记，可继续下一条；有多条时避免连续展示同一条，只有一条时仍可阅读。回顾与漫步展示完整正文及原生定位，使用现有安全渲染边界；空集合提供空状态。回顾支持左右滑动以及可聚焦的前后翻页操作，页面退出恢复原卡片流及草稿。
- D7：沿用 CommonJS、原生 DOM/CSS、宿主 API 和现有构建，无新增依赖。用户文案走 `i18n/zh_CN.json`；保留 44px 触控、键盘访问、aria、亮暗主题与减少动态效果。页面实现须与已提供设计和参考图做截图比较。

## Delivery

1. **已有内容进入卡片流**：把加入入口、并集查询、来源与编辑/移出操作作为完整交付。隔离内核建立普通段落、列表、引用、超级块、标题、代码和表格，观察加入或原生标签变化后，卡片流、第二段关键词搜索、标签计数和热力图一致变化；验证重复命中只算一条，移出后的原始内容仍可从思源读取，原生速记的编辑删除继续成立。涉及已有结构的写入先在隔离内核证明 ID 和子块保留，再接 UI。
2. **重新阅读历史内容**：建立两个本地视角入口与翻阅页，消费第 1 项的统一集合。观察同日重新进入与重载不重抽、新一天生成当日顺序、改变数量不打乱已有顺序、移出后不显示失效内容；验证空集合和单条集合。按设计比较移动与桌面、亮暗主题截图，并操作原生定位和返回。
3. **本地交付验证**：整合后运行既有测试、必要的数据语义回归、构建及产物语法检查。通过真实隔离宿主观察块菜单→卡片→编辑/移出→搜索统计和回顾的消费路径；性能只报告本次实测样本规模，不沿用一期数值作为二期结论。临时探针放 `.scratch/`，保留的截图与交付说明放 `docs/design/acceptance/`，最终阅读全部差异并提交本地变更。

## Status

二期本轮范围和混合收录的移出行为已确认，计划已细化。Delivery 1–3 尚未验收，准备按顺序派发 Sol 实施。录音转写等待 V4/V5；flomo 导入本轮暂不做；V1–V3 和真机验收仍保留。未推送、部署或修改个人笔记。
