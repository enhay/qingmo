# 轻墨 · 可行性调研

- 日期：2026-10-11
- 调研对象：本机思源 3.8.5（只读接口实测）、思源 `master` 源码（`app/src`、`kernel/api`）、插件 API 类型定义 `siyuan-note/petal`、思源集市当前 565 个移动端可用插件
- 标注约定：**【实测】** 在本机思源上调用接口看到结果；**【源码】** 读源码确认；**【推断】** 有依据但没验证，后面写明怎么验证；**【官方】** 来自厂商官方文档；**【第三方】** 来自社区文章，时效和准确性要再核对；**【未知】** 目前查不到

## 结论

**可以做，自己开发。** 一期需要的能力都已经核实存在：手机上全屏速记、卡片流、标签、图片、热力图。

开工前必须在真机或双设备上验证三件事（见第 5 节 V1–V3）。其中 V1（两台设备同一天都记了内容，同步时会不会丢）决定"每天一个文档"这个数据模型要不要调整。二期开始前，再验证手机上能不能录音（V4）、转写服务在国内能不能访问（V5）。AI 洞察直接复用思源自带的 AI 接口，不需要另建服务（见 2.5）。

不在「轻语」基础上改，原因有两个：它的主数据放在插件私有的 JSON 文件里，不是思源的块；仓库里也没有源码。

### 2.4 转写服务（Cloudflare Worker 加令牌）

| 项目 | 结论 | 依据 |
|---|---|---|
| Workers 免费版额度 | 每天 10 万次请求；每个请求 **CPU 时间 10ms**（等待网络不计入 CPU 时间）；内存 128MB；每个请求最多 50 次子请求 | 【官方】[Workers Limits](https://developers.cloudflare.com/workers/platform/limits/) |
| Workers Paid 额度 | 每个请求的 CPU 时间默认 30 秒，最长 5 分钟；不限请求数 | 同上 |
| 请求体大小 | 按 Cloudflare 账户套餐算，免费账户 100MB，远大于速记录音的体积 | 同上 |
| 免费版够不够用 | 签名本身很便宜。"一句话识别"要把音频转成 base64 塞进 JSON，几百 KB 到几 MB 的音频可能逼近 10ms 的上限 | 【推断】V5 实测，超了就上 Paid（每月 5 美元） |
| 国内能不能访问 | 国内社区普遍说 `*.workers.dev` 被墙，做法是绑定托管在 Cloudflare 的自有域名；Cloudflare 官方也建议生产环境用自定义域名 | 【第三方，时效未知】[掘金文章](https://juejin.cn/post/7247451971946299452)；【官方】[Workers 路由](https://developers.cloudflare.com/workers/configuration/routing)。V5 必须在不开代理的国内网络下实测——你本机开着全局代理，自己测不出问题 |
| 不过关时的退路 | 把同一套接口部署到国内节点（腾讯云 EdgeOne 或云函数），插件只改服务地址常量 | 【推断】接口约定和部署平台无关 |
| 令牌存储 | 用 D1 存令牌哈希、额度和用量；每次转写都要写一次用量，D1 比 KV 更合适（KV 免费版的写入次数额度较小） | 【推断】D1 和 KV 的免费额度上线前再核对一次官方页面 |

### 2.5 复用思源的 AI 设置（AI 洞察）

| 项目 | 结论 | 依据 |
|---|---|---|
| 有没有能直接调用的接口 | 有两个，都不流式，都返回字符串：① `POST /api/ai/chatGPT {msg}`：插件自己拼好内容发过去，会带上共用的历史对话（见下面一行）；② `POST /api/ai/chatGPTWithAction {ids, action}`：内核按块 ID 读出内容，填进 `action` 模板里的 `{{input}}` 位置（模板里没有占位符时，就把 `action` 当前缀），每次调用互相独立 | 【源码】`kernel/api/ai.go`、`kernel/model/ai.go`（`ChatGPT`、`ChatGPTWithAction`、`BuildAIEditorPrompt`、`chatGPTComplete`） |
| 用哪个模型 | `Conf.AI.GetEditingModel()`，也就是"编辑"用的模型。用户在思源里换了模型，轻墨跟着换 | 【源码】`chatGPTComplete` |
| 你本机的配置 | 已经配好：服务商 DeepSeek，"编辑"用 DeepSeek V4 Flash，请求超时 120 秒 | 【实测】`/api/system/getConf`（只读，没有读出密钥） |
| **坑 1：失败也返回成功** | 没配服务商时，内核弹出自己的提示，然后返回空字符串；模型调用出错时也返回空字符串。两种情况的 `code` 都是 0 | 【源码】`isOpenAIAPIEnabled`、`ChatGPTWithAction` |
| **`/api/ai/chatGPT` 的共用上下文（已选用这个接口）** | 它把每轮的问答追加进内核进程里的一个全局变量 `cachedContextMsg`，下次调用时整段带上（最多保留"编辑"设置里的历史条数，你本机是 57 条）。只有发送消息 `Clear context` 或重启内核才会清空，而且所有调用这个接口的插件和脚本共用这一份。思源自己的编辑器 AI 已经不走这个接口了（前端源码里只剩一个类型声明，编辑器用的是 `/api/ai/editor/chat`，历史由调用方自己传）。**轻墨的用法**：每次洞察前后各发一次 `Clear context`；接受和别的插件同时调用时内容互相串的低概率风险 | 【源码】`kernel/model/ai.go` 的 `chatGPT()`、`chatGPTComplete()`；`app/src` 里查不到调用 |
| 流式输出 | `/api/ai/editor/chat` 是 SSE 流式接口，参数是 `ids`、`input`、`action`、`history`。它会自带一段"行内编辑引擎，只输出要插入的内容"的系统提示词 | 【源码】`aiEditorSystemPrompt`、`NewAIEditorChatStream` |
| 权限 | 这些接口都要求管理员身份（`CheckAdminRole`）。思源本地客户端默认就是管理员 | 【源码】router.go |
| 手机上能不能用 | 手机端跑的是同一个内核，接口一样 | 【源码】 |
| 手机上要不要再配一次 AI | 大概率要：AI 设置保存在 `conf/` 目录，思源同步一般只同步 `data/` 目录 | 【推断】在手机上打开「设置 → AI」看一眼就能验证 |
| 内容长度 | 内核把所有选中的块拼成一段发出去，不做截断 | 【源码】`getBlocksContent`。插件必须自己控制范围的总字数 |
| 选 `chatGPT` 而不是 `chatGPTWithAction` 的原因 | `chatGPTWithAction` 由内核读块内容：每个块导出成标准 Markdown，块之间只用空行隔开。**没有创建时间，条与条之间也没有明确分界**。`chatGPT` 的内容由插件自己拼，可以每条带上时间、标签和分隔 | 【源码】`getBlocksContent` → `ExportNodeStdMd` |
| 内核自带的进度提示 | 调用期间内核会推送"Requesting..."进度提示，调用结束才清掉 | 【源码】`chatGPTComplete` 中的 `PushEndlessProgress`。在手机上会不会盖住轻墨的全屏层，留到二期验证 |

## 3. 数据模型可行性

**已定方案**：每条速记是一个超级块，加一个标记属性；每天的速记放在一个独立文档里，不写进思源日记。

- **只有一份数据**：卡片流显示的就是文档里的块。在思源编辑器里改了，卡片流跟着变；在卡片流里改了，文档也跟着变。思源的全局搜索、块引用、反链都能直接用。
- **查询**：按属性查出所有速记，按 `created` 倒序排列、分页加载。热力图按 `substr(created,1,8)` 分组统计。
- **用户在编辑器里拆掉了超级块怎么办**：这条速记会从卡片流里消失，内容还在文档里。这个行为可以接受，写进使用说明。

### 同步冲突风险（最大的风险）

你本机的同步配置【实测】：开启自动同步，用 S3 存储，**"生成冲突文档"是关闭的**。

- **推断**：两台设备在两次同步之间，都往同一天的文档里追加了速记 → 同一个文件在两边都被改了 → 同步时只保留一边，另一边新写的速记只能在"文件历史"里找回。轻语只有一个 JSON 文件，冲突范围更大（所有记录），不是每日文档模式独有的问题。
- **发生条件**：两台设备都在离线状态下记了内容，或者两边都在线、但在同一个同步间隔内都记了内容。如果你以手机为主，频率应该很低，但发生了就会丢数据，所以必须实测（V1）。
- **V1 不通过时的备选**（到时候请你决定）：
  - (a) 每天每台设备一个文档，例如 `2026-10-11` 和 `2026-10-11 (iPhone)`。需要放弃严格的"一天一个文件"。
  - (b) 打开"生成冲突文档"，插件识别冲突副本并合并回去。

### 同一天出现两个文档

两台设备都在离线时创建了当天的文档，就会出现两个路径相同的文档。这种情况**不丢数据**，卡片流也不受影响（它按属性查询，不看文档）。后期可以加一个"合并同一天的文档"的维护操作。

如果改成用日期生成固定的文档 ID，两边就会创建同一个文件，问题又回到上面的同步冲突。所以**不用固定 ID**。

## 4. 键盘和输入体验

- flomo 的输入面板贴在键盘上方（见截图 3）。插件可以用 `visualViewport` 的尺寸变化，加上 `mobile-keyboard-show`/`hide` 事件来定位面板。
- 【未知】输入框聚焦时，思源自己的键盘工具栏（`#keyboardToolbar`）会不会冒出来、挡住输入面板。原生 App 键盘弹出时会调用 `window.showKeyboardToolbar`，它是否只在编辑器聚焦时显示，源码上还没确认。待真机验证（V2）。
- 语音输入：一期直接用输入法自带的"点击说话"（截图 3 的键盘上就有），不需要开发。

| V1 | 两台设备同一天记的内容在同步后都保留 | 手机和电脑都断网，各往同一天的速记文档追加 1 条，再联网同步 | 两台设备上，这一天都能看到 2 条速记 |
| V2 | 全屏界面加键盘在真机上可用 | 写一个最小插件：全屏层加一个 textarea，在 iPhone 和安卓上各试一次 | 输入框不被键盘挡住；思源的键盘工具栏不冒出来（冒出来要能隐藏）；刘海和底部安全区正常 |
| V3 | "启动后直接进入轻墨"可行，草稿能保留 | 在 `onLayoutReady` 里弹出全屏层，冷启动、从后台切回各试一次；在输入框里打几个字后杀掉 App 再打开 | 冷启动后 2 秒内出现输入面板；安卓返回键关掉的是速记层，不会直接退出 App；杀掉 App 重开后，`localStorage` 里的草稿还在（iOS 和安卓都要测） |
| V4（二期前） | 手机上能录音 | 最小插件调用 `MediaRecorder` | iOS 和安卓都能录出音频，记下各自的 MIME 类型 |
| V5（二期前） | 转写服务能用 | 最小 Worker：校验令牌、调用腾讯云、返回文字，绑定自有域名；在**不开代理**的国内手机网络下，从思源手机端调用 | 能连通；30 秒录音从发出请求到拿到文字不超过 5 秒；记录 Worker 的 CPU 时间是否超过免费版的 10ms；WebView 直接 `fetch` 跨域能通（不通就改走 `forwardProxy` 再测） |
