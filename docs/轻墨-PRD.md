# 轻墨 · 产品需求文档

- 产品名：轻墨（QingMo），插件 ID `siyuan-qingmo`，属性前缀 `custom-qingmo-`
- 版本：v0.2 草稿，2026-10-11
- 状态：待评审。第 10 节的同步冲突策略要等 V1 结果再定
- 依据：[可行性调研](轻墨-可行性调研.md)、[设计规格](design/轻墨-design.md)（视觉和交互以它为准），以及 flomo 手机端截图 5 张（[reference/](design/reference/)）
- 官方帮助对照：[flomo 参考与交互细节](design/flomo参考与交互细节.md)，说明现有输入、组合筛选、AI 解读的细节及与官网新版功能的差异，不改变分期和数据口径。

## 1. 背景与目标

**问题**：在思源手机端记一个闪过的念头，要先打开 App，找到文档，进入编辑器，再定位光标，步骤太多，所以碎片想法都记到了 flomo 里，散落在思源之外。flomo 体验好，但数据不在自己的笔记系统里，没法和思源里的知识做引用、搜索和回看。

**目标**：轻墨要在思源手机端提供 flomo 那样的体验——打开就能写，写完就走，之后用卡片流回看——并且每条速记都是思源的原生块。

**自用期的成功标准**：

1. 开启"启动后直接进入轻墨"后，冷启动思源 2 秒内就能打字，不需要任何点击；没开启时，从思源主界面进入输入最多点 1 次。
2. 点发送后 1 秒内，这条速记出现在卡片流最上面。
3. 连续用 4 周，新的碎片想法全部记在思源里，不再打开 flomo。

**远期目标**：自己用顺手以后付费公开。这对一期有三条约束：

- 属性名带插件专属前缀；
- 界面文字全部走 i18n 文件，不在代码里写死；
- 不写死任何个人路径、笔记本或凭据。

## 2. 用户与场景

| 场景 | 现在怎么做 | 用了轻墨以后 |
|---|---|---|
| 地铁上冒出一个想法 | 打开 flomo | 打开思源，直接在输入面板写，发送 |
| 看到一张海报或书页想留下来 | 拍照存相册，之后就忘了 | 输入面板里点图片，选图或拍照，配一句话发送 |
| 走路时不方便打字 | 用 flomo 录音 | 一期用输入法的"点击说话"；二期在轻墨里录音并自动转写 |
| 晚上回看当天记了什么 | 在 flomo 里翻 | 卡片流按时间倒序；侧边栏看热力图，按标签筛选 |
| 在电脑上整理 | 从 flomo 复制到思源 | 速记本来就在思源的每日文档里，可以直接引用、移动、展开写 |

## 4. 数据模型（已定，以后改要做数据迁移）

### 4.1 每日文档

- 每天的速记放在一个独立文档里，**不写进思源日记**。
- 位置 = 笔记本 + 路径模板。默认模板是 `/轻墨/{yyyy}/{MM}/{yyyy-MM-dd}`，文档标题就是日期。第一次使用时让用户选笔记本（你自用时选「碎碎念」），不预设任何笔记本。
- 文档上加属性 `custom-qingmo-day="20261011"`。写入时先按这个属性找当天的文档，找不到再按路径找，都找不到就新建。这样用户把文档挪了位置或改了名字，也不会再多建一个。
- 归属哪一天按**发送时手机的本地日期**算。

### 4.2 每条速记

- 每条速记是一个超级块（`{{{row … }}}`），块属性 `custom-qingmo-memo="1"`。超级块里可以放多个段落、图片、列表，二期还会放音频。
- 写入时一次调用 `appendBlock` 完成，Markdown 内容如下：

  ```
  {{{row
  正文第一段 #读书#

  ![](assets/xxx.png)
  }}}
  {: custom-qingmo-memo="1"}
  ```

- **时间**：用块自带的 `created`，不另外存时间字段。
- **标签**：用户输入的 `#标签` 后面接空格、换行或到结尾时，保存时转成思源的 `#标签#`。支持多级标签 `#a/b`。
- **编辑**：用 `updateBlock` 写回 Markdown，**写回时必须带上 `custom-qingmo-memo` 属性**，否则这条速记会从卡片流里消失（验收项）。
- **删除**：用 `deleteBlock`，删除前要确认。删除后可以在思源"文件历史"里找回，确认弹窗里要说明这一点。
- **在编辑器里直接改**：属性还在，卡片流就照常显示；用户拆掉了超级块，这条就不再算速记，内容还留在文档里。
- **只认属性，不按位置收录**：没有 `custom-qingmo-memo` 属性的块一律不进卡片流、搜索和统计，包括用户在每日文档里直接打的字、同一笔记本里的其他笔记。已有的块要成为速记，只能由用户手动「加入轻墨」（二期，见第 6 节），加入的块额外带 `custom-qingmo-added="1"`，用来区分删除方式。

### 4.3 统计口径

| 指标 | 怎么算 |
|---|---|
| 笔记数 | 带 `custom-qingmo-memo` 属性的块总数 |
| 标签数 | 这些块里出现过的标签去重后的个数 |
| 天数 | 今天减去第一条速记的日期，再加 1（和 flomo 一样） |
| 热力图 | 最近 12 周每天的速记条数，颜色分 4 档 |

## 6. 二期需求概要

- **录音和转写**：
  - 输入面板里点麦克风开始录音，再点一次停止。音频上传到 assets，作为音频块放进这条速记，再发给转写服务把录音转成文字，写进正文。
  - 转写走你自建的转写服务，用令牌鉴权，见第 7 节。插件里不出现任何腾讯云凭据。
  - 转写失败时保留音频，卡片上显示"重新转写"。
- **AI 洞察**：是一个"视角"列表（界面见 design 2.4），每日回顾是其中一个视角。
  - **每日回顾**（二期）：每天随机抽 N 条历史速记（N 可以设置），以卡片堆的形式左右翻看（design 2.5）。同一天内抽到的结果固定不变，按日期做随机种子。
  - **随机漫步**（二期）：随机显示一条历史速记，可以接着翻下一条。
  - **AI 视角**（预留，没做出来之前不在列表里显示）：
    - AI 解读统一由项目内的 [qingmo-insights Skill](../skills/qingmo-insights/SKILL.md) 定义：入口负责共同规则和视角路由，分析时按需读取对应 Reference。六个视角的方法依据与改编说明见 [公开 Skill 来源](../skills/qingmo-insights/references/sources.md)。目前只备好 Skill，插件入口的上线时点仍待定。
    - 视角展示配置为 `{id, title, author, description, kind: "local" | "ai", reference, needsScope}`，不再存独立的 `prompt` 正文。AI 视角的 `reference` 指向 Skill 内的方法文件；每日回顾和随机漫步是 `local`，不使用该字段。
    - **复用思源自己的 AI 设置**，不自建服务、不另收费。用的是思源「设置 → AI」里给"编辑"选的模型（你本机现在是 DeepSeek V4 Flash），费用由用户自己的 AI 账号承担。
    - **调用 `/api/ai/chatGPT`**，每次洞察的步骤：
      1. 先发一条 `{"msg": "Clear context"}`，清掉内核里共用的历史对话；
      2. 插件自己用 SQL 读出范围内的速记，**带上原始块 ID、创建时间和标签**，按字数上限（默认 3 万字，超出只取最近的）控制材料，并说明实际提供的范围；插件按视角 ID 读取 `SKILL.md` 和对应 Reference，再与笔记拼成消息。此接口没有文件读取工具，按需加载由插件完成，不能只把文件路径交给模型；
      3. 把拼好的内容作为 `msg` 发出，返回的字符串就是洞察结果；
      4. 离开洞察页时再发一次 `Clear context`，避免这次的速记内容留给别的调用方。
    - **为什么不用 `chatGPTWithAction`**：那个接口由内核读块内容，读出来的只有正文，没有创建时间，而"什么时候想的"对洞察很重要。用 `chatGPT` 时，内容怎么拼由插件自己决定。
    - **接受的风险**：`chatGPT` 的历史对话是内核里所有调用方共用的。如果别的插件恰好在同一时间也调用它，双方内容会串，轻墨的 `Clear context` 也会清掉对方的历史。用户同时做洞察和用其他 AI 插件对话的可能性很低，所以接受。思源自己的编辑器 AI 不走这个接口，不受影响。
    - **调用时要注意的几点**（详见可行性调研 2.5）：
      - 接口失败时也返回 `code: 0`，只是内容为空，所以**空字符串要当作失败处理**；
      - 这个接口不是流式的，模型写完才返回，最长等到用户设置的超时时间（你的是 120 秒）。界面要显示"正在洞察…"，并且能取消（取消只是不再等结果，内核那边的请求停不下来）；
      - 内核调用期间会弹出自己的"Requesting..."进度提示，要在手机上看它会不会盖住轻墨的界面。
    - 没有配置 AI 时，点 AI 视角弹出引导："在思源「设置 → AI」里添加模型后即可使用"，并且能直接跳到这个设置页（`openSetting(app, "ai")`）。
    - 洞察结果写成思源文档 `/轻墨/洞察/{yyyy-MM-dd}-{视角名}`，加属性 `custom-qingmo-insight="<视角 id>"`。这样结果也是思源原生数据，可以搜索和引用。
    - 以后想要边生成边显示，可以换成 `/api/ai/editor/chat`（SSE 流式，历史由调用方自己传，不用全局变量）。注意它会自带一段"行内编辑引擎"的系统提示词，换之前要先试一下对洞察结果有没有影响。
- **手动加入轻墨**：把思源里已有的块收为速记，不自动收录任何内容。
  - **入口**：思源编辑器的块菜单（点块标）里加「加入轻墨」；已经是速记的块显示「移出轻墨」。文档本身、已是速记的块及其内部的子块不显示「加入轻墨」。
  - **写入**：只给这个块加上 `custom-qingmo-memo="1"` 和 `custom-qingmo-added="1"`，不移动、不包成超级块、不改内容。块仍在原文档原位置。
  - **时间与统计**：时间用块自带的创建时间，按这个日期进热力图；笔记数、标签数、天数按第 4.3 节照常计算，所以加入很早的块会让"天数"变大。
  - **卡片展示**：和普通速记卡片相同，另有三处不同：
    1. 时间下方显示来源"来自《文档名》"，点击在思源中定位到这个块；块在轻墨每日文档里时不显示来源。
    2. 卡片菜单的「删除」换成「移出轻墨」：只去掉两个属性，内容保留在原文档。确认弹窗要说明这一点。
    3. 段落和超级块可以在轻墨输入框里编辑，写回时保留两个属性；其他类型（标题、表格、嵌入、代码块等）只给「在思源中编辑」，避免整体写回时丢结构。
  - **不做**：按笔记本、文档或标签批量自动收录；把非速记笔记以只读卡片混进卡片流。
- **从 flomo 导入**：解析 flomo 导出的 HTML，按原来的时间放进对应日期的文档，并且保留原时间。具体做法待定：要么用 `createDocWithMd` 时指定块 ID 来写入原时间，要么另存一个原时间属性。

## 7. 转写服务与令牌（二期建，三期复用为激活码）

### 7.1 架构

```
轻墨插件 ──(HTTPS，Authorization: Bearer <令牌>)──▶ 转写服务（Cloudflare Worker，绑定自有域名）
                                                    ├─ D1：令牌、额度、用量
                                                    └─ 腾讯云语音识别（凭据只存在 Worker 的 secret 里）
```

- **令牌就是将来的激活码**：二期你给自己发一个令牌，用来转写；三期卖出去的激活码也是同一种令牌，只是额度、到期时间和可用功能不同。插件和服务端都不需要第二套授权机制。
- **腾讯云凭据**：用只有语音识别权限的 CAM 子账号，SecretId 和 SecretKey 用 `wrangler secret` 存进 Worker，不进代码仓库，也不下发给插件。
- **插件怎么调用**：插件直接 `fetch` 转写服务，Worker 返回跨域响应头（`Access-Control-Allow-Origin: *`，因为不用 cookie，靠令牌鉴权）。手机 WebView 要是拦截了跨域请求，退一步改走思源内核的 `forwardProxy`（V5 验证）。
- **服务地址**：写成插件里的一个常量。换地址时发新版插件，不提供设置项。

### 7.2 接口约定

**POST `/v1/transcribe`**：转写一段录音

- 请求头：`Authorization: Bearer <令牌>`，`Content-Type` 填音频格式（`audio/mp4`、`audio/webm`、`audio/wav`）
- 请求体：原始音频的二进制内容。大小上限在 V5 实测后定，先按 5MB 设计
- 成功返回 `200`：`{"text": "转写结果", "durationSec": 12.4, "quota": {"remainingSec": 3480}}`
- 失败返回统一格式：`{"error": {"code": "…", "message": "…"}}`

| HTTP 状态 | `code` | 什么情况 | 插件怎么提示用户 |
|---|---|---|---|
| 401 | `token_invalid` | 令牌不存在或已被停用 | 令牌无效，请检查设置里的令牌 |
| 401 | `token_expired` | 令牌过期 | 令牌已过期 |
| 402 | `quota_exceeded` | 转写时长用完了 | 本期转写时长已用完 |
| 413 | `audio_too_large` | 音频超过大小上限 | 录音太长，请分段录 |
| 415 | `audio_unsupported` | 格式不支持 | 这种录音格式暂不支持 |
| 429 | `rate_limited` | 请求太频繁 | 稍后再试 |
| 502 | `asr_failed` | 腾讯云返回失败 | 转写失败，可稍后重试；录音已保存 |

**GET `/v1/token`**：查询令牌状态。设置页的"验证"按钮调用它；三期判断付费功能是否可用也调用它。

- 返回 `200`：`{"status": "active", "plan": "self", "expiresAt": "2027-10-11T00:00:00Z", "features": ["transcribe"], "quota": {"totalSec": 36000, "usedSec": 1520}}`
- 失败时同上表的 401 系列

### 7.3 服务端数据（D1）

- `tokens` 表：令牌的 SHA-256 哈希（**不存明文**）、套餐、状态（启用/停用）、到期时间、总额度（秒）、已用（秒）、备注、创建时间
- `usage` 表：令牌哈希、时间、音频时长、是否成功
- 计量口径：按腾讯云返回的音频时长计，**只有转写成功才扣额度**
- 令牌格式：`qm_` 加 32 位随机 base62 字符。二期手工发放（`wrangler d1 execute` 插一行就行），不做管理后台

### 7.4 插件端

- 令牌存在插件设置里（`saveData`），随思源同步到你的所有设备；显示时打码，只露后 4 位。
- 设置页的"验证"按钮调用 `/v1/token`，显示状态、到期时间、剩余转写时长。
- 三期需要校验付费功能时，用 `/v1/token` 的结果，在本机缓存 7 天，离线时也能正常使用。缓存过期后再联网校验。

## 8. 非功能要求

- **离线**：思源内核在本机运行，没网也能记，有网后自动同步。转写需要联网，离线录的音会留在这条速记里，标为"待转写"。
- **隐私**：一期不向外发送任何数据。二期只把音频发给轻墨的转写服务，由它转发给腾讯云；服务端不保存音频，只记时长。三期上架时，隐私说明里要写明这一点。
- **外观**：轻墨的全屏层按 [design](design/轻墨-design.md) 的固定配色还原 flomo，只跟随思源的亮色/暗色模式；悬浮按钮、侧滑面板入口、桌面端侧栏用思源的 CSS 变量。
- **无障碍**：所有图标按钮都有 `aria-label`，触控区域至少 44pt，深色和浅色主题下对比度都达到 WCAG AA。
- **兼容性**：`minAppVersion` 定为开发时实测过的最低版本，一期只保证当前稳定版。
- **性能**：5000 条速记时，卡片流首屏不超过 1 秒，热力图查询不超过 300ms；一段 30 秒的录音，从停止录音到文字出现不超过 5 秒（V5 实测后再校准）。

## 9. 风险

| 风险 | 影响 | 怎么处理 |
|---|---|---|
| 两台设备往同一天的文档里写，同步时一边被覆盖（V1） | 丢失一边当天的速记，只能从文件历史找回 | 开工前先做 V1；不通过时在第 10 节第 1 项的两个备选里选一个 |
| 手机键盘和思源自己的键盘工具栏挡住输入面板（V2） | 核心体验不成立 | 开工前先做 V2 |
| 国内网络访问 Cloudflare 不稳定（V5）。国内社区普遍说 `workers.dev` 子域名被墙，但没有权威的最新来源 | 不开代理的国内用户转写失败 | 必须绑定自有域名；V5 在不开代理的国内手机网络下实测。不过关就把同一套接口部署到国内节点（例如腾讯云 EdgeOne 或云函数），插件只改服务地址 |
| Workers 免费版每个请求只有 10ms CPU 时间 | 给大段音频做 base64 编码和签名可能超时 | V5 实测；超了就升级 Workers Paid（每月 5 美元，单请求 CPU 时间默认 30 秒） |
| 令牌泄露后被别人用来转写 | 消耗你的腾讯云费用 | 每个令牌有额度和到期时间，可以随时停用；按令牌限速 |
| 思源升级后插件 API 变了 | 入口或界面失效 | 只依赖 `petal` 公开的 API；内核接口只用常用的那几个 |
| 集市对收费的态度不明确 | 三期发布方式受影响 | 三期前去官方渠道确认 |

## 10. 待决事项

1. **同步冲突策略**（等 V1 结果）：V1 通过就保持现在的设计；不通过就在两者里选一个：(a) 每天每台设备一个文档；(b) 打开"生成冲突文档"，由插件把冲突副本合并回来。
2. **腾讯云用哪个接口**（V4、V5 之后定）：60 秒以内用"一句话识别"，更长的用"录音文件识别极速版"或"录音文件识别（base64 直接上传）"。上限和支持的音频格式要以官方文档为准，安卓录出来的 webm 格式能不能直接识别是关键。
3. **付费模式**（三期）：买断还是订阅，转写时长怎么定价，哪些功能收费，激活码怎么卖、怎么发（发卡平台还是自建支付）。

已定：
- 产品名「轻墨」，属性前缀 `custom-qingmo-`；
- 转写费用由服务端承担，用令牌控制额度，令牌就是将来的激活码；
- AI 洞察复用思源自己的 AI 设置，模型和费用都由用户自己负责，不经过转写服务。
