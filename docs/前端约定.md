# 轻墨 · 前端约定（Svelte）

界面代码的写法约定。产品行为看 [PRD](轻墨-PRD.md)，界面尺寸看 [设计规格](design/轻墨-design.md)，交付顺序看[二期计划](plans/2026-10-12-phase-two.md)。代码形成了与本文不同的写法时，在同一个提交里改本文，不让两者长期不一致。

## 技术栈

- Svelte 5，只用 runes 写法：`$state`、`$derived`、`$effect`、`$props`。不用旧写法：`export let`、`$:`、`createEventDispatcher`、`on:click` 指令、`svelte/store`。
- 构建用 Vite 和 `@sveltejs/vite-plugin-svelte`，产出思源可加载的单个 CommonJS `dist/index.js` 与 `dist/index.css`；`siyuan` 保持外部模块。版本以 `package-lock.json` 锁定，安装用 `npm ci`。
- 只有三个开发依赖：`svelte`、`vite`、`@sveltejs/vite-plugin-svelte`。不用 TypeScript、SvelteKit、UI 组件库、状态管理库、CSS 框架或图标库。新增任何依赖都先问用户。
- 源码统一用 ES 模块（`package.json` 设 `"type": "module"`），测试用 `node --test` 直接导入。

## 目录

| 目录 | 放什么 | 规则 |
|---|---|---|
| `src/index.js` | 插件入口：生命周期、注册入口、挂载和卸载视图 | 只做接线，不写业务逻辑 |
| `src/core/` | 收录查询、历史、回顾抽样、设置合并、AI 材料组织与来源校验、腾讯云签名、音频转换 | 不导入 `svelte`，不碰组件；除音频转换等必须用浏览器接口的模块外，都能在 Node 里直接测试 |
| `src/state/` | 插件实例持有的共享状态：设置、AI 请求、转写进行状态 | 文件名 `*.svelte.js`，导出工厂函数，由插件实例创建一次；不写模块级单例 |
| `src/editor/` | 可编辑区核心（现有编辑器逻辑）和它的 Svelte 包装 | 核心不依赖 Svelte；包装组件只负责挂载、传参和销毁 |
| `src/components/` | 复用组件：菜单、底部面板、对话框、轻提示、分组列表、音频条等 | 不直接读写共享状态，只通过 props 和回调交互 |
| `src/views/` | 页面级组件：卡片流、输入面板、侧栏、每日回顾、随机漫步、AI 洞察各页、设置 | 从上下文拿共享状态和操作 |
| `src/styles/` | 全局 token（设计规格第 3 节）和少量全局样式 | 组件样式写在各自的 `<style>` 里 |

## 状态与数据

- 每个插件实例只有一份共享状态。挂载视图时用 `setContext` 放进去，视图用 `getContext` 取。标签页、侧栏和手机入口拿到的是同一份。
- 设置只通过 `saveSettings(patch)` 写：以当前共享值合并改动，再写 `settings.json`，写完所有视图自动刷新。组件里不保存设置副本；表单编辑中的值是草稿，提交时只传改动的字段。
- 组件不直接调用思源内核接口，统一走 `src/core/` 或共享状态里的操作。这样内核调用、错误处理和历史留存只有一处。
- 派生数据用 `$derived`。`$effect` 只用来同步 DOM 或外部资源，并返回清理函数，用于移除监听、停止计时器、断开录音流。
- AI 请求和转写请求都要能丢弃迟到结果：发起时生成一个请求标识或 `AbortController`；视图销毁、用户取消或输入框关闭后，返回的结果一律不写入页面、不创建文档、不改笔记。

## 渲染与安全

- `{@html}` 只能用于经过现有 `safeHTML` 净化的 Lute 输出。笔记正文、模型输出、腾讯云返回值都不能直接进 `{@html}`。
- 链接只放行 `siyuan://blocks/`、`http(s)://`、`mailto:`、站内 `assets/`；模型输出里的来源链接先按 PRD 6.6.2 核对 ID。
- 腾讯云密钥只从共享设置读取，不写进日志、`console`、错误提示、笔记或 AI 材料。

## 样式与无障碍

- 颜色、字号、圆角、阴影只用设计规格第 3 节的 `--qm-*` token，不在组件里写死颜色。
- 手机与桌面由根节点的 `data-layout` 区分，沿用现有约定；暗色由思源主题驱动。
- 可点击的东西用 `<button>` 或 `<a>`。图标按钮要有 `aria-label`，触控区域至少 44pt；展开类控件写 `aria-expanded`；菜单支持方向键、Enter 和 Esc（设计规格 2.7）。
- 动画遵守 `prefers-reduced-motion`。
- 界面文字全部走 `i18n/zh_CN.json`，组件里不写中文字面量。

## 测试与验证

- `src/core/` 的逻辑用 `node --test` 测，断言只锚定返回值、写入或读回的字段、显式状态属性和错误码。
- 组件不写单元测试，不对文案、CSS、DOM 层级或快照断言。界面按计划用截图对照验收；需要给测试或截图脚本定位状态时，加 `data-state` 之类的显式属性。
- 命令：`npm run build` 构建，`npm run dev` 监听构建，`npm test` 跑测试。
